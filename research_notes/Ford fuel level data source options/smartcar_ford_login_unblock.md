# Getting a Smartcar Connect authorization past Ford's login (US, 2021 F-250 gas + 2021 Expedition, as of 2026-10-25)

Scope note: the Ford web-auth failure ("Sorry, we experienced an error!") on 2026-07 and 2026-10-25 is taken as given. These notes cover (a) Smartcar support + what a Connect session id is for, (b) the iOS SDK path and whether it yields a `user_id` usable by a separate backend on Vehicle API v3, (c) Ford-account-side causes of Ford login errors, (d) Smartcar 2026 pricing and fuel-signal compatibility for the two trucks. Everything labeled CONFIRMED has a primary source; INFERRED is my reasoning from those sources.

## Key Question 1: What is a Connect "session id" used for, how do you reach Smartcar support, and how do you escalate a failed OEM login?

### Takeaway
The session id is the identifier Smartcar's own ticket form asks you to paste when reporting a Connect failure; there is no public doc explaining what support does with it beyond using it to look up the Connect session in their logs. Ticket submission (support.smartcar.com) is gated to Build/Custom (paid) plans; the only published fallback is `support@smartcar.com`, which Smartcar itself named in the Oct 16, 2026 Ford incident resolution. No published turnaround/SLA exists.

## Key Question 2: Does the Smartcar iOS SDK produce a `user_id` usable server-side in v3, and what exactly are the mechanics?

### Takeaway
CONFIRMED from the SDK source: the iOS SDK (`SmartcarAuth`) renders Connect in a `WKWebView`, and when Connect needs an OEM login it sends a JSON-RPC `oauth` message to the native SDK, which opens the OEM login in an `ASWebAuthenticationSession` and relays the OEM callback URL back into Connect. The completion handler returns `userId` (plus `code`, `state`, `virtualKeyUrl`, `externalId`). The `user_id` is the same Smartcar-generated UUID that v3 docs tell you to send as `sc-user-id`; the client secret is never used by the SDK, and with `responseType: "none"` no code exchange is needed at all. Smartcar's docs tie the connection to "your application" (client id), not to the channel used to complete Connect.

### Cited Findings
**iOS SDK mechanics (CONFIRMED from source)**
- Connect page is presented in a `WKWebView` (`webView = WKWebView(frame: .zero, configuration: webviewConfiguration)`), not `SFSafariViewController`/`ASWebAuthenticationSession`. Redirect detection is in `WKNavigationDelegate.decidePolicyFor` by matching `host == redirectUriHost`, then cancelling navigation, calling `handleCallback(url)`, and dismissing. No custom user agent or headers are set. — [ConnectController.swift](https://raw.githubusercontent.com/smartcar/ios-sdk/master/SmartcarAuth/ConnectController.swift)
- OEM login path: `OAuthCapture.swift` registers a `"SmartcarSDK"` script message handler; Connect posts a JSON-RPC `oauth` request with `authorizeURL` and `interceptPrefix`; the SDK then "Starts the OEM login flow for the given `oauth` RPC request using an ASWebAuthenticationSession" (`ASWebAuthenticationSession(url: authorizeURL, callbackURLScheme: interceptPrefixScheme, ...)`). On completion it relays the whole callback URL (`OauthResult(returnUri: callback.absoluteString)`) back to Connect via `evaluateJavaScript`; errors are `-32000` (login cancelled) / `-32603` (internal). A separate `complete` RPC signals a redirect-less flow finished. — [OAuthCapture.swift](https://raw.githubusercontent.com/smartcar/ios-sdk/master/SmartcarAuth/OAuthCapture.swift)
- Callback parsing in `SmartcarAuth.swift` reads these query params: `code`, `state`, `virtual_key_url`, `user_id`, `external_id`, `error`, `error_description`, `status_code`, `error_message`, `vin`, `make`. — [SmartcarAuth.swift](https://raw.githubusercontent.com/smartcar/ios-sdk/master/SmartcarAuth/SmartcarAuth.swift)
- Completion handler signature: `func completionHandler(code: String?, state: String?, virtualKeyUrl: String?, userId: String?, externalId: String?, err: AuthorizationError?)`, with the README comment "Exchange code for access token or use userId with M2M access token." `responseType: "none"` is "for flows like M2M tokens that don't need an authorization code" (then `code` is nil and the result is delivered directly to the completion handler). Initializer takes only `applicationId`, `redirectUri`, `scope`, `responseType`, `completionHandler` — no client secret. Redirect URI format `sc<clientId>://<hostname>` (e.g. `scafb0b7d3-...://exchange`), required only when `responseType` is `"code"`. iOS 13+. Installable via SPM or CocoaPods. — [smartcar/ios-sdk README](https://github.com/smartcar/ios-sdk)
- Recent SDK versions: v6.3.0 had an SPM checksum issue closed Apr 2026 (#105/#106); "Xcode 26/Swift 6.3 Runtime Issue" closed Apr 20, 2026 (#104); open issue #111 (Jul 15, 2026) about surfacing the selected brand on cancellation. No issues mention Ford. — [ios-sdk issues](https://github.com/smartcar/ios-sdk/issues?q=is%3Aissue)

**Smartcar's own statements about mobile vs web for Ford (CONFIRMED)**
- Incident "Ford/Lincoln: Elevated error rates for web auth login attempts": Investigating post (timestamped Jul 15, 2026 22:55 UTC): "If you're using our mobile SDKs, both Android and iOS are fully supported and working. No action is needed." and "If you're relying on web-based authentication, this flow is not available at the moment. We recommend transitioning to our mobile SDK if applicable." Update Oct 15, 2026 22:42 UTC: since 10:40 UTC Oct 15, NA Ford/Lincoln owners and EU Ford owners via mobile SDKs "can't connect or re-authenticate vehicles... can sign in to Ford, but the connection fails afterward with error=server_error. Already-connected vehicles aren't affected." Monitoring Oct 16 02:06 UTC: "A fix has been successfully implemented for mobile SDKs... Web-based authentication continues to be unavailable." Resolved Oct 16 22:37 UTC: "The issue has been resolved. All systems are now operating normally." — [Brand Reliability incident c3n88sb87hm4](https://brandreliability.smartcar.com/incidents/c3n88sb87hm4); [Brand Reliability home](https://brandreliability.smartcar.com/)

**v3 / client-credentials model (CONFIRMED)**
- Connect's "Handle the response" page: `user_id` = "A Smartcar-generated UUID that identifies this user"; store it with your internal user id; it is the value for the `sc-user-id` header. `external_id` echoed back if set. If you launch Connect with `response_type=none` and no `redirect_uri`, "there is no response to handle" and you look up the connection on the `/connections` endpoint. — [Connect: handle the response](https://smartcar.com/docs/connect/handle-the-response.md)
- API Authentication how-to: "the redirect URL now includes a `user_id` parameter alongside the authorization code"; token via POST `https://iam.smartcar.com/oauth2/token` with `grant_type=client_credentials`, `client_id`, `client_secret` (form body); "These credentials grant access to all vehicles connected to your application"; `sc-user-id` header required "When accessing vehicle signals or issuing commands"; `GET https://vehicle.api.smartcar.com/v3/connections?filter[userId]={userId}` lists a user's vehicles. — [API authentication](https://smartcar.com/docs/getting-started/how-to/api-authentication.md)
- M2M FAQ: access is "scoped to your application rather than to an individual vehicle"; "No changes to your Connect flow are required"; tokens valid 3600 s, no refresh tokens; `userId` also appears in webhook payloads under `user.id`. — [M2M FAQ](https://smartcar.com/docs/getting-started/how-to/m2m/faq.md)
- Dashboard config: redirect URIs are needed only for `response_type=code`; "Apps using application access tokens can skip registering one." Custom-scheme URIs must be `sc{clientId}://{hostname}` and are "the redirect format for mobile applications"; multiple URIs may be registered; first one is default. — [Connect dashboard config](https://smartcar.com/docs/connect/dashboard-config.md)
- Connect SDK overview: "our frontend SDKs only handle integrating Connect into your application. You will still need to use a backend SDK to manage tokens and make API requests." — [Connect SDKs](https://smartcar.com/docs/connect/connect-sdks.md)

### Inferences
- INFERRED (high confidence): A throwaway Xcode app using `SmartcarAuth` with the project's existing `applicationId`/client id, `scope: ["read_fuel", "read_vin", "read_vehicle_info"]` (plus whatever the backend needs), and `responseType: "none"` will, on success, hand back `userId` in the completion handler. That UUID is exactly what the backend already expects as `Smartcar__UserId` / `sc-user-id`; no code exchange and no client secret on-device are required. With `responseType: "code"` (default) you must register an `sc<clientId>://exchange` redirect URI in the Dashboard and you still get `user_id` on the callback without exchanging the code.
- INFERRED (high confidence): The connection is owned by the application (client id). Smartcar's docs consistently say credentials "grant access to all vehicles connected to your application" and never distinguish by channel; mobile-SDK and web Connect both produce the same `user_id`/connection objects (the SDK parses the same `user_id` param the web redirect carries). Treat "same application id" as the requirement, not "same channel".
- INFERRED (medium confidence): Why mobile worked while web failed in Jul–Oct 2026: the iOS SDK opens Ford's login in an `ASWebAuthenticationSession` (a Safari-backed, system browser context) rather than inside Smartcar's Connect web page/iframe context. Smartcar did not publish a root cause, so this is a plausible mechanism, not a confirmed one.
- INFERRED: Even if the user never ships an app, the iOS Simulator can run `ASWebAuthenticationSession`; however the `oauth` RPC path uses a custom-scheme callback (`interceptPrefix`), which works in the Simulator. A real device is the safer test if Ford fingerprints the browser.
- INFERRED: After a successful mobile Connect, verify via `GET /v3/connections?filter[userId]=...` (client-credentials token) that the Ford VINs appear — this is also the documented way to find `user_id` after a `response_type=none` flow if you missed it.

### Gaps
- Smartcar does not publish whether a `user_id` created under application A is usable by application B; assume no (docs scope everything to "your application").
- I could not confirm from Smartcar whether web auth was in fact restored on Oct 16, 2026 — the Resolved post is generic and the user's 2026-10-25 failure suggests web auth remained broken or re-broke.
- The exact Ford OEM `authorizeURL` Smartcar hands the SDK (and therefore which Ford SSO host it uses) is not visible in the SDK source; it comes from Connect at runtime.

## Key Question 3: Known Ford-account-side causes of Ford web-login errors and reported fixes (2025–2026 preferred)

### Takeaway
No public source quotes the exact "Sorry, we experienced an error!" text in a Smartcar/Ford context. The documented Ford-side causes of third-party login failure are: (1) Ford's security team suspending or force-resetting accounts linked to third-party/automation tools (error code CSIAH0320E; suspension emails; recurring password resets), with an April 2026 report naming Smartcar specifically; (2) ordinary lockouts ("Too many login attempts", Aug 2026) cleared by Forgot Password or Ford Account support; (3) credential/password-format mismatches fixed by resetting the password on ford.com; (4) FordPass in-app browser/default-browser bugs (Jul 2026, fixed by app 6.16.1). Ford's official guidance is: verify credentials, reset password, clear browser cache/cookies, then call 1-800-392-3673.

## Key Question 5: Is Ford fuel level (`internalcombustionengine-fuellevel` / `read_fuel`) supported for a 2021 F-250 (gas) and 2021 Expedition?

### Takeaway
CONFIRMED via Smartcar's public Compatibility API (queried 2026-10-25, no auth): `FORD-F-250-2019-2026-ICE-US` and `FORD-Expedition-2018-2027-ICE-US` both list signals `internalcombustionengine-fuellevel` (Fuel Level, permission `read_fuel`), `internalcombustionengine-range` (`read_fuel`), and `internalcombustionengine-amountremaining` (`read_fuel`), plus odometer, location, tires, oil life, doors/locks, VIN, and lock/unlock commands. Charge/battery groups are "notApplicable"; `incompatible: []`.

Record `FORD-F-250-2019-2026-ICE-US` capabilities include `{"name":"Fuel Level","group":"InternalCombustionEngine","code":"FuelLevel","capability":"internalcombustionengine-fuellevel","permission":"read_fuel"}`, `internalcombustionengine-range` (`read_fuel`), `internalcombustionengine-amountremaining` (`read_fuel`), `internalcombustionengine-oillife` (`read_engine_oil`), `odometer-traveleddistance`, `location-preciselocation`, `wheel-tires`, closures, VIN, `closure-lock`/`closure-unlock`. Record `FORD-Expedition-2018-2027-ICE-US` lists the same fuel signals. Also present: `F Super Duty 2022-2025`, `F-350`, `F-450 Super Duty 2020-2026`. — [Smartcar Compatibility API (live query)](https://compatibility.api.smartcar.com/v3/compatible-vehicles?filter[make]=FORD&filter[region]=US); API docs: [compatibility API intro](https://smartcar.com/docs/api-reference/compatibility-api-intro.md)
- The compatibility endpoint is public ("needs no credentials or headers"), data "comes from real connections on the Smartcar platform and updates daily", pagination params are ignored, and Smartcar recommends caching daily. — [compatibility API intro](https://smartcar.com/docs/api-reference/compatibility-api-intro.md)
- Smartcar's compatibility page warns support "can exhibit variability based on trim, optional packages, firmware version, and active subscriptions." — [Smartcar compatible vehicles](https://smartcar.com/product/compatible-vehicles)
- Signals reference: `internalcombustionengine-fuellevel` = "The current amount of fuel in the vehicle's tank, expressed as a percentage (0 - 100)"; `-amountremaining` (liters), `-range` (km), `-oillife` (percent). — [InternalCombustionEngine signals](https://smartcar.com/docs/api-reference/signals/internalcombustionengine.md)
- Smartcar's Ford page: works with "all Ford models that support the FordPass app"; owners "log in with their Fordpass Connect account". — [Smartcar Ford page](https://smartcar.com/ford)
- Smartcar fuel product page: fuel level, percent, and range; "Works on 2015 and newer vehicles"; "latency and frequency of data availability may vary between makes and models." — [Smartcar fuel product](https://smartcar.com/product/fuel)
- Feb 8, 2024 changelog: `GET /fuel` extended to Ford in supported European countries (shows Ford fuel was already live in the US earlier). — [Smartcar changelog Feb 2024](https://smartcar.com/docs/changelog/2024/february)

### Inferences
- INFERRED: Both trucks are squarely inside the model-year ranges Smartcar reports from real connections, so compatibility is not the blocker; the Ford SSO step is. Request scope should include `read_fuel` (fuel level/range) and optionally `read_odometer`/`read_vin`.

### Gaps
- The record is for "F-250" ICE without a diesel/gas split; the user's gas F-250 is covered by the ICE record, but Smartcar does not break out engine type.
- Smartcar does not publish per-model data latency for Ford; the fuel product page only warns it varies.
