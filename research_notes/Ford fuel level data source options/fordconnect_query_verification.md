# FordConnect Query (developer.ford.com) — verification for a US individual owner, as of 2026-10-25

Method note: Ford's portal is a client-rendered SPA, so it was opened in the Claude desktop built-in browser (read-only; no sign-in, no account creation, no form submission, no terms accepted). The FordConnect Query product/API-reference page (`/apis/fordconnect-query`) redirects to the home page when not signed in, and the NA onboarding page (`/developer-na`) shows only a two-step summary plus a "Sign In" button, so Ford's own text on the "personal use" checkbox, rate limits, pricing and the API reference is NOT publicly visible. Everything below is labelled **[Ford text]** (captured from Ford's own pages or Ford emails quoted verbatim by developers), **[Community text]**, or **[Own probe]** (an HTTP request I made to Ford's auth endpoint without credentials).

## KQ1. Does Ford's own portal text say who may register (individuals, personal use, regions)?

Yes, on two public pages. Ford's changelog says **"2026 - January: FordConnect Query launched for personal use in NA region"** (after a Sept 2025 launch), and the public Ford Developer Program Terms and Conditions are written for "the individual or legal entity" and grant only "a personal, revocable, limited ... license ... for personal, non-public development use only", with testing allowed "only with Your vehicle(s)". The actual registration form (where the community reports a "personal use" option) is behind sign-in and could not be captured.

### Inferences
- A 2-hour polling cadence (FordFuelAlert's schedule) is roughly 100x below what community integrations run, so quota is very unlikely to matter; the vehicle-side "polling disabled to conserve battery" behaviour is the more relevant risk, and it is a cloud/vehicle policy, not an API quota.

### Gaps
- Ford's documented call-volume limits, token quotas, and whether a sandbox/mock vehicle exists are all behind sign-in; no community source quotes them.

## KQ3. What FordConnect Query exposes for ICE vehicles; auth model; freshness; per-vehicle consent

### Takeaway
Community code and a US ICE F-150 debug dump show a single `/fcon-query/v1/telemetry` document with per-metric values and per-metric `updateTime`s including `fuelLevel` (percent, can exceed 100), `fuelRange` (km), `odometer`, `ignitionStatus`, `position` (lat/lon), 12 V `batteryStateOfCharge`, oil life and tyre pressures, plus a root `updateTime`. Auth is OAuth 2.0 authorization code on Ford's Azure AD B2C tenant with `openid offline_access`; refresh tokens stop being issued 365 days after the owner's last consent (Ford email, Oct 2026). The API is read-only cloud-cached data; no wake-up/refresh endpoint exists in the Query API.

### Cited Findings
- **[Ford text]** "explicit customer authorization ... consent-driven process ... OAuth 2.0 authorization code flow and granular scopes". — [developer.ford.com/apis](https://developer.ford.com/apis)
- **[Community text, code]** Endpoints: `FORD_BASE_URL = "https://api.vehicle.ford.com"`; authorize `.../fcon-public/v1/auth/init`; token `.../dah2vb2cprod.onmicrosoft.com/oauth2/v2.0/token?p=B2C_1A_FCON_AUTHORIZE`; query base `.../fcon-query/v1` with `/garage`, `/telemetry`, `/vehicle-health/alerts`, `/wallbox`, `/electric/departure-times`, `/electric/charge-schedules`, `/fccs?startDate=&endDate=`. — [const.py](https://github.com/marq24/ha-fordconnect-query/blob/main/custom_components/fordconnect_query/const.py)
- **[Own probe, 2026-10-26 02:10 UTC]** `GET https://api.vehicle.ford.com/fcon-public/v1/auth/init` returns HTTP 400 JSON "Required request parameter 'client_id' ... is not present"; with client_id but no state: 400 "Required request parameter 'state'"; with a dummy client_id and state: 404 `{"error":"404 NOT_FOUND","message":"credential not found"}`. So the endpoint is live and validates `client_id`, `state`, `redirect_uri`, `response_type`, `scope` server-side before redirecting. — [auth/init](https://api.vehicle.ford.com/fcon-public/v1/auth/init)
- **[Community text, code]** Field mapping: fuel = `metrics["fuelLevel"]["value"]`, state `round(fuel_level)`, "Values above 100 are not clamped or filtered"; range = `metrics["fuelRange"]["value"]` (km, localised); odometer = `metrics["odometer"]["value"]` (monotonic guard: new value accepted only if ≥ previous); position = `metrics["position"]["value"]["location"]` with `lat`/`lon`/`alt`, `gpsCoordinateMethod`, `gpsDimension`; ignition = `metrics["ignitionStatus"]`; last refresh = root `updateTime`; 12 V battery = `batteryStateOfCharge` (percent). No refresh/wake-up function; handler "only reads from the cached data dictionary". — [fordpass_handler.py](https://github.com/marq24/ha-fordconnect-query/blob/main/custom_components/fordconnect_query/fordpass_handler.py); [const_tags.py](https://github.com/marq24/ha-fordconnect-query/blob/main/custom_components/fordconnect_query/const_tags.py)
- **[Community text, README 2026]** Sensor table lists "Fuel Level (can be > 100%)" for petrol/diesel and (P)HEV; integration is "ONLY READ"; polls "every 60 seconds"; "Position data may be stale, because Ford need not send a new GPS fix every minute". — [README](https://github.com/marq24/ha-fordconnect-query)
- **[Community text, Jul 2026, US 2024 ICE F-150]** Telemetry dump dated 2026-07-10 contained 12 V battery SoC 48%, fuel level and range, odometer 44,802, oil life 28%, tyre pressures, ignition OFF; "Several values were last updated on July 10, while engine oil temperature was last updated June 19" (per-metric timestamps). — [Issue #42](https://github.com/marq24/ha-fordconnect-query/issues/42)
- **[Community text, Sep 4 2026]** Issue/discussion titled "Kilimeterstand (odometer) nicht mehr verfügbar" (odometer no longer available) — body not retrieved. — [Issue #48](https://github.com/marq24/ha-fordconnect-query/issues/48); [Discussion #49](https://github.com/marq24/ha-fordconnect-query/discussions/49)
- **[Ford email quoted by developer, Oct 13-14 2026]** FordDev Team: "FordConnect requires users to perform account-linking every year"; expiry = `auth_time` claim in the `id_token` + 365 days; "Beyond this point, refresh tokens will no longer be issued"; "we cannot adjust, extend, or grant exceptions to these timelines" (Cyber Security requirement). Client secret has a separate expiry shown in the portal (example: app registered ~Jan 2026 shows secret expiry 2028-01-18). — [Release 2026.10.0](https://github.com/marq24/ha-fordconnect-query/releases/tag/2026.10.0); [Issue #52](https://github.com/marq24/ha-fordconnect-query/issues/52)
- **[Community text]** Consent flow steps: HA opens "the Ford login page"; "Sign in with your Ford account"; "select the radio button, scroll down, and press the Consent button"; "If several vehicles are registered, select the radio button for the one to connect"; then redirect with authorization code. "Error after pressing Consent: The app's global deployment is probably not finished ... up to 2 hours after registration." — [CONFIGURE_INTEGRATION.md](https://github.com/marq24/ha-fordconnect-query/blob/main/docs/CONFIGURE_INTEGRATION.md)
- **[Community text]** Vehicle prerequisite: "latest on-board modem functionality" and "registered/authorized with the FordPass/The Lincoln Way app". Recommends a separate FordPass account for the integration. — [README](https://github.com/marq24/ha-fordconnect-query)
- **[Community text, legacy FordConnect v3, ~2024]** Node-RED package (for `api.mps.ford.com/api/fordconnect/v3`, NOT Query): "Access token is valid for 20 minutes"; had explicit `refresh-vehicle-status`/`refresh-vehicle-location` nodes; Ford advised to "be mindful of how often the vehicle is polled". — [@tally/fordconnect-node-red](https://flows.nodered.org/node/@tally/fordconnect-node-red); [evcc api.go](https://github.com/evcc-io/evcc/blob/master/vehicle/ford/connect/api.go)

### Inferences
- For a 2021 F-250 gas and 2021 Expedition (both FordPass Connect 4G modem vehicles), the ICE signal set (fuelLevel, fuelRange, odometer, ignitionStatus, position, 12 V battery, oil life, tyre pressure) should be the same shape as the 2024 F-150 dump; but no source covers those exact model years. Fuel-level >100% must be clamped client-side (FordFuelAlert's `PercentRemaining` 0–100 mapping already needs `Math.Min(100, …)`).
- Freshness: Query returns the cloud's last-known values with per-metric `updateTime`; it does not trigger a vehicle wake-up. Values may be days old for a parked vehicle (the F-150 dump had a metric 3 weeks stale), so FordFuelAlert should record and surface the metric's `updateTime` rather than assume "now".
- Token model for FordFuelAlert: store refresh token; access token lifetime unknown for Query (20 min was the legacy v3 figure); plan for a forced annual re-consent and a client-secret rotation (~2 years).
- The "granular scopes" are chosen as "data categories" at app registration; community guides say select all; per-vehicle consent happens at the Ford consent page (vehicle radio button), not in the FordPass app.

### Gaps
- No Ford API reference captured: exact scope names, telemetry JSON schema, units, access-token TTL, and whether `/garage` returns VIN/model year. Odometer availability after Sep 2026 is unresolved (issue #48 body not read).
- Whether a newly consented vehicle must be the primary FordPass account's vehicle vs an invited driver is unresolved (July 2026 case where an invited driver saw "no vehicle" at consent; issue #19).

## KQ4. Does the consent flow share Smartcar's Ford web login, and were there "Sorry, we experienced an error" reports Jul–Oct 2026?

## KQ5. marq24/ha-fordconnect-query specifics (registration, endpoints, fuel quirk, polling, 429, known issues, Ford statements) and evcc / Node-RED corroboration

### Takeaway
The repo (v2026.10.7, 25 Oct 2026) is the de-facto reference: register your own OAuth app per region portal with "personal use", all vehicle types and all data categories; wait ≥2 h; consent via Ford login; poll `/fcon-query/v1/telemetry` every 60 s (min 30 s) with Retry-After-aware 429 handling. Known 2026 issues are registration-form errors (Jan–Feb), consent 500s for cross-region apps, a Ford-side consent outage (Jun 17–18), recurring backend blips (Jul–Oct), odometer disappearing (Sep), and Ford's annual re-linking email (Oct). No account suspensions attributed to Query were found. evcc still documents the EU portal and a 15-min cache; the Node-RED package targets the legacy v3 API.
